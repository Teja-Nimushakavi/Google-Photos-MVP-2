# Evaluation Plan: Smart Suggestions MVP

This document outlines the evaluation criteria, testing strategies, and success metrics required to validate the completion of each phase defined in the `implementation_plan.md`. 

---

## Phase 1: Project Setup & Scaffolding
**Objective:** Ensure the foundational architecture is correctly established and cross-platform capabilities are ready.

### Evaluation Criteria:
- **Environment Check:** Developers can successfully clone the repository and run the setup scripts without errors.
- **Backend Health:** Running the backend server locally exposes a successful health-check endpoint (e.g., `GET /health` returns `200 OK`).
- **Frontend Build:** The React Native/Expo app successfully compiles and launches on both a Web browser and a Mobile simulator without crashing.
- **Code Quality:** CI/CD pipeline successfully runs linters (ESLint, Prettier, Ruff/Black) and blocks commits that violate style guidelines.

---

## Phase 2: Data Model & Mock Dataset
**Objective:** Validate that the mock data accurately simulates real-world metadata and is accessible by the backend.

### Evaluation Criteria:
- **Schema Validation:** The `photos_dataset.json` strict-matches the defined `PhotoEntity` schema (no missing mandatory fields, correct data types).
- **Data Coverage:** The dataset contains at least 50 photos with a diverse distribution across all contextual categories (Location, People, Environment, Activity, Time, Photo Type).
- **In-Memory Loading:** The backend successfully loads the JSON dataset into memory on startup in under 500ms.
- **Query Unit Test:** A basic internal script can fetch a photo by its ID or by a simple category filter (e.g., fetching all "Indoor" photos returns the correct subset).

---

## Phase 3: Core Backend Engines
**Objective:** Ensure the Retrieval and Smart Suggestion engines return mathematically correct and contextually appropriate responses.

### Evaluation Criteria:
- **Baseline Retrieval Testing:** 
  - A query for a known exact match (e.g., "Goa cafe") returns the correct photo object with a high relevance score.
- **Poor-Result Detection Evaluation:**
  - A query designed to fail (e.g., "snowboarding in desert") correctly triggers the `needs_refinement = true` flag in the API response.
- **Suggestion Pruning (Edge Case Eval):**
  - If a query contains "Indoor", the suggestion engine *must not* return an `[Indoor]` chip.
- **Lookahead Constraint Test:**
  - Every suggestion chip generated by the engine guarantees at least one resulting photo if selected. No "dead-end" chips are generated.
- **API Response Time:** `GET /api/search` responds in under 200ms (P95) to ensure the UX feels snappy.

---

## Phase 4: Frontend Development (Web & Mobile)
**Objective:** Validate the UI/UX, cross-platform consistency, and proper state management of the search experience.

### Evaluation Criteria:
- **Visual Regression / Layout:**
  - The photo grid and search bar render correctly on mobile screens (iPhone/Android) and scale gracefully on desktop web browsers.
- **State Management (Multi-select):**
  - Tapping a suggestion chip adds it to the active filter state. Tapping it again removes it.
  - The UI instantly displays a loading spinner when a chip is tapped while the backend processes the refined query.
- **API Integration:**
  - The frontend correctly parses the `needs_refinement` flag and renders the suggestion chips dynamically.
- **Race Condition Prevention:**
  - Rapidly tapping 3 chips debounces the API calls, resulting in exactly 1 final API request with all 3 chips included, rather than 3 overlapping requests.

---

## Phase 5: Testing, UX Polish & Deployment
**Objective:** Confirm the end-to-end user journey works flawlessly in production and tracks success metrics accurately.

### Evaluation Criteria:
- **End-to-End (E2E) Journey:**
  - **Test Case:** User searches "Goa food" -> 0 results -> Taps `[Cafe]` -> Taps `[Friends]` -> Success! Relevant photo is displayed. (Pass/Fail)
- **Deployment Verification:**
  - The Web App URL is publicly accessible and functionally identical to the local build.
  - The Backend URL handles cross-origin requests (CORS) correctly from the frontend.
- **Analytics Tracking:**
  - Selecting a suggestion chip successfully fires a `suggestion_engaged` event in the analytics dashboard.
  - Reaching a successful photo view after refinement fires a `search_recovered` event.
- **Primary Metric Baseline:** 
  - After internal UAT (User Acceptance Testing) with 5 participants, the *Successful Retrieval Rate* metric is measurable and > 0%.
